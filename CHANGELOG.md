# Changelog

Notable changes per release. Older releases predate this file — see the
[GitHub releases](https://github.com/acking-you/POCOX/releases) for their
autogenerated commit lists.

Versions are `0.MINOR.PATCH`: while the major is 0, a **minor** bump is where a
breaking change goes.

## Unreleased

- The CLI is now `pocox`. The installers update an existing `pocket-codex` CLI
  in place (also in an explicit `POCKET_CODEX_BIN_DIR`) and keep that name as an
  alias, so scripts and systemd units written for it keep working, and workers
  it started stay manageable after the upgrade. Release archives carry the
  alias too (a symlink in the tarballs, a copy of the binary in the Windows
  zip). A release from before the rename installs under its own name.
  Release asset names are unchanged.

## 0.4.0 — 2026-10-18

- `pocket-codex serve --allow-remote-management` lets other devices manage a
  CLI host (for example a systemd unit in WSL or on a server) exactly like a
  desktop: add, edit, apply and stop its Codex, OpenCode and Claude services.
  Saved choices survive restarts, a service that cannot start is reported
  instead of taking management down, and `pocket-codex status` lists it. See
  [CLI host](docs/remote-device-management.md#cli-host).
- Windows, each WSL distribution and every separate installation on one
  computer now publish under their own stable name, so they can be hosted side
  by side. The services page keeps this computer's controls on its own entry,
  names devices as `studio (WSL Ubuntu)` and shows the platform each host
  reports. **Breaking:** a host started without `--device` publishes under its
  new installation name once; pick it again in the host switcher. Hosts with an
  explicit `--device` keep their name.
- A turn that completes while the running-sessions list refreshes no longer
  shows as running again until the next refresh (most visible on Windows).
- Conversations Codex Desktop ran in its managed worktrees are listed under
  the project they came from, instead of as more projects of the same name.
- Phones: a long-pressed message darkens in its own outline instead of
  showing a dark border; opening the sessions list by swiping gives one light
  haptic when it lands and no longer raises the keyboard from its search
  field; a parent row's fold control sits inside the row's highlight.
- Phones: the conversation's status bar keeps its state and change counts on
  one line, shortening the model and branch names (then hiding the model and
  clock) instead of overflowing. The services device list scrolls, a host's
  session rows put their status and action under the title when narrow, and
  the folder picker stacks its buttons with large text.

## 0.3.0 — 2026-10-17

- Host ACP v1 agents through a configurable executable and argument list, with
  the Claude adapter as a preset. Native Codex app-server stays
  independent. Shared controls follow negotiated capabilities; the host owns
  agent lifecycle, permissions and bounded history, including remote control
  through the relay. See [ACP agents](docs/acp-agents.md) for verified scope.
- Host OpenCode natively (`opencode serve`, `opencode:<name>` service keys)
  instead of through `opencode acp`, with its own configuration and sign-ins.
  Opening a Claude or OpenCode session resolves its access automatically
  (write, or follow with the reason) instead of the Session control dialog.
  **Breaking:** the `opencode acp` preset, its model-catalog plugin and its
  custom provider routes are removed; saved OpenCode ACP agents and restore
  records are dropped, so host OpenCode again from the hosting editor. A host
  can use a per-host custom provider (Responses, Anthropic Messages or Chat
  Completions), which offers every model the gateway lists, not just the
  default model; Apply reconnects open views automatically. New ACP and
  OpenCode conversations ask for a project folder before sending. See
  [Native OpenCode](docs/opencode-native.md) for verified scope.
- On macOS, Cmd+Q, the application menu and the Dock quit stop owned hosts
  first, like the tray's Quit, instead of leaving their processes running.
- Run several OpenCode hosts on one device: each uses OpenCode's shared
  database (one host at a time) or a history of its own.
- Manage another desktop's services from any device: add, edit, apply and
  stop hosts there through its management-only `host` key (no remote paths,
  installs or sign-ins). Each host has a default project folder, and the
  status page is concise with copyable diagnostics.
- Phones: the sessions list lies under the conversation and a horizontal
  swipe anywhere moves it aside; layouts reflow by measured room instead of
  squeezing, and new conversations use the space above the composer.
- Refresh the visual design: calm graphite neutrals with the logo blue as the
  one accent, layered desktop pages with translucent floating controls,
  quieter forms and Markdown messages. The app icon is unchanged; the macOS
  menu bar shows a one-colour mark in the bar's own colour.
- Review a conversation's edits or the working tree in a resizable sidebar
  (an overlay on narrower windows, a page on phones) with lazy diffs, gap
  expansion and a whole-file view. Paging history or jumping to a turn no
  longer moves what is on screen.
- Hosting operations show progress on their own button and confirm with a
  toast. The sessions list shows a skeleton until the host answers, and a
  relay that cannot be reached is explained on its own card while this
  computer's hosts keep working.
- Calls and dictation on iOS and Android give the audio back to other apps
  when they end.
- macOS releases are signed with Developer ID and notarized, the Dock icon
  stays blue in light and dark mode, and theme switching works in release
  builds again.

## 0.2.5 — 2026-09-26

  configurable 512 MB shared budget. Evict older windows and previews first,
  prioritizing the current session and recently refreshed running sessions.
- Render cached history before reconnecting, then request verified window and
  text deltas from compatible hosts. Cached content stays read-only until fresh
  state arrives; settings expose cache usage, capacity, and disabling persistence.
- Default new, unconfigured conversations to **Auto / 替我审批**, using Codex's
  automatic approval reviewer with the workspace sandbox. Keep manual approval,
  read-only, full-access, and existing saved permission choices available.
- Offer a **Fast** toggle when the selected model advertises support. Restore its
  saved state and explicitly return to the default service tier when disabled.
- Queue messages sent during a running turn for the next turn by default. Choose
  **Supplement / 补充说明** to send text and attachments to the current turn's
  next step instead.

  a queued send restores its contents without losing newer composer drafts or
  attachments.
- Keep rejected supplements editable, preserve newer drafts on late responses,
  and retain the accepted turn ID after reopening a running session so turn
  navigation does not show an extra turn.
- Clear Fast when switching to an unsupported default model and retry model
  discovery after cold-open connection failures, with bounded backoff.
- Reject history pages and pending checkpoints from a replaced source generation;
  honor cache quota changes during outstanding writes and recover cleanly from
  partial records or concurrent rollout appends.

## 0.2.0

### ⚠️ Upgrading

**Rebuild or reinstall every client.** A 0.1.x app or CLI cannot connect to the
relay at all. The broker data path it used is gone, and production now runs
`--legacy-protocol deny`, which is a *requirement* of the new design rather than
hardening: the pre-v2 protocol lets any key-holder register any key.

Self-hosters have one config change: `:7666` must be publicly reachable, so
`deploy/README.md`'s former "firewall the relay to loopback (MANDATORY)" no
longer applies. Drop `broker_listen` from `config.toml` — it is no longer read —
and set `relay_addr` to the address clients should dial.

### Clients talk to the relay directly

The backend used to carry every byte: each stream was tunnelled through it, with
a control tunnel, one data tunnel per stream, and a per-stream rendezvous. That
cost an extra hop on every message and made backend availability a prerequisite
for two of your own devices to reach each other.

It now only authenticates a GitHub login and vends a short-lived per-account
credential; after that handshake it is off the data path entirely. Isolation
moves from the network to the credential — the relay confines each credential to
its own namespace, so an account cannot address another's services whatever key
string it presents.

Also swaps the vendored pb-mapper submodule for the published 0.5 crate, which
removes a whole class of client/relay version skew: the pinned 0.2.x client could
not decode the 0.5 relay's structured over-quota error, read a permanent refusal
as a transport fault, and reconnected without backoff.

Account and self-host mode were separate implementations down to parallel
subscribe / probe / register paths; they now differ in two values, so both
crates' worth of broker code is deleted rather than maintained.

### Fixed

- **An account could be locked out permanently.** A client whose token refresh
  failed would retry, and every retry re-revoked the whole token family —
  including the session just created by signing in again — so recovery was
  impossible while the old client ran. Reuse detection is now idempotent and
  bounded by issue time.
- **Desktop browser sign-in never completed.** Two stacked causes: the callback
  redirect named `localhost`, which resolves to IPv6 on Windows while the
  listener binds IPv4 only; and once that was fixed, the landing page's Chinese
  text crashed the listener mid-response, because the plugin writes the body as
  latin-1.
- **Self-host setup had no way out** — reached by a route that replaces the
  stack, with no back button, so the only exits were finishing setup or killing
  the app.
- **A service could read "connected" while its conversation read
  "disconnected".** The two screens tracked link state separately and neither
  could see the other.
- **`meta GET … connection closed before message completed`.** A pooled
  keep-alive connection goes stale when a supervised service restarts; that is a
  transport hiccup, so it is retried now. The meta client also honoured the
  system HTTP proxy while only ever talking to loopback, which broke on machines
  whose proxy exceptions miss `127.0.0.1`.
- Windows launcher and tray icons were blurry. The launcher `.ico` held a single
  256 px frame that Windows downscaled 8:1 for the 32 px taskbar; the tray's
  glyph is only ~72% of its tile, so a 16 px frame gave the mark ~10 px. Both now
  render each size at its target resolution, and the small tray frames zoom the
  artwork.

### App

- **A turn's tool calls and reasoning fold into one row** — "已处理 2m 31s",
  expandable to the work, and again to an individual call's output. A single
  question used to put a wall of alternating command / reasoning / search rows
  between itself and its answer. A running turn stays open so you can watch it.
- **A turn rail** down the left edge: one tick per turn, hover to preview, click
  to jump. It reshapes as you scroll, so it doubles as a position indicator.
  Short conversations keep the corner arrows, which say more at three turns than
  a rail of three ticks.
- **Device-first navigation.** Secondary pages are unified, and a device's
  capabilities — chat, API, session sharing — are listed together rather than
  split across protocol tabs.
- **Editable conversation titles**, persisted server-side via upstream codex's
  `thread/name/set`, so a rename follows the thread rather than the device.
- **A codex-style sidebar tree** grouping conversations under their project, an
  activity view, and desktop cursors on interactive elements.
- **A two-state theme toggle.** It used to cycle system → light → dark, so its
  next state was unguessable from its icon and a tap could land on "follow the
  OS" — which looks like nothing happened when the OS already matches. Settings
  still offers follow-system.
- The desktop UI is aligned on the Flow design system (palette, type scale,
  metrics), with the brand assets recoloured onto the accent.
- The composer no longer repeats the project name once a thread exists: the chip
  was a label you could not act on, above the field you type in.

### Internal

- `deps/codex` updated to upstream main (1771 commits). The bridge needed no
  adaptation.
- Retry handling converged onto one bounded policy instead of several ad-hoc
  loops.
- The Flutter session screen and its 7,200-line test suite were split by
  responsibility; duplicated transport, token, and diff helpers were shared.
