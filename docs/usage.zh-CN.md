# POCOX 使用指南

> English version: [`docs/usage.md`](usage.md)

一台机器保持登录 Codex，你的其它设备来驱动它。设备之间通过后端互相找到，有两种
方式：**匹配码**，完全不需要账号；或者**同一个 GitHub 账号**。两种方式都无需配置
中转地址（relay）或共享密钥：后端给你的设备发放凭据，它们在中转上相遇。

> 想自建中转（relay）？见 [CLI › Self-host](cli.md#self-host)。
> 想自己部署后端？见 [`deploy/README.md`](../deploy/README.md)。

---

## 0. 开始之前

- 必须有一个**可访问的 `pocox-backend`**。它由某个人部署一次（你自己，
  或服务器的拥有者）。CLI 和 App 内置了一个默认后端；如需指向你自己的后端，给
  `login` 或 `pair` 加上 `--backend https://你的主机`（会被记住），或在 App 的高级设置里
  填写。
- **宿主机**（对外暴露 Codex 的那台）需要在 `PATH` 中有可用的 `codex` 程序。
  客户端设备**不需要**安装 Codex——除非走 CLI 的 `connect` 路径（它会在本地
  运行 `codex --remote`）。

## 1. 用匹配码登录

每台设备有一个自己的匹配码，形如 `K7M2-F9QX-3RTB`。用匹配码关联起来的设备算作同一个
用户，可以互相访问对方的服务。不涉及任何账号、邮箱或手机号。后端需要开启匹配码登录
（见[部署](../deploy/README.md#pairing-code-login-optional)）。

### 第一台设备

打开 App。电脑会显示它自己的匹配码和二维码，点 **开始使用**。手机首先给出一个输入
其他设备匹配码的框，所以在第一台设备上点 **这是我的第一台设备**。在终端里，
`pocox pair` 会显示匹配码并询问是否设置这台设备。

### 添加设备

在新设备上输入或扫描你已在用的任意一台设备的匹配码：电脑上点 **输入其他设备的匹配码**，
手机上用输入框（或旁边的扫描按钮），终端里用 `pocox pair join`。下一页会列出这个组里
的设备；在你点 **关联** 之前，什么都不会关联。要让新设备看到匹配码，在已在用的设备上
打开 **设置 › 账户 › 添加设备**。

拿到匹配码的人可以立即关联一台设备，不需要任何批准，并使用你托管的服务；你的设备只会在
事后收到提示（“Pixel 已关联。不是你的设备？”）。所以只给你自己的设备看。如果匹配码泄露了，
在它所属的设备上立即关掉 **允许通过匹配码关联**（`pocox pair pause`），在 **设置 › 账户**
里移除不认识的设备（`pocox devices remove`），等匹配码发放满一天后再 **更换匹配码**
（`pocox pair rotate`）。

### 二维码或链接只会打开预览

扫描匹配码二维码，或打开 `pocox://pair` 链接，只会填入匹配码并显示和手动输入时一样的
预览，绝不会自己完成关联。链接能在 iOS、Android 和 macOS 上打开 App；在 Windows 和
Linux 上请手动输入匹配码。

### 恢复设备

重装或重置后丢失了身份的设备（见下文），在 **其他登录方式** 里选 **恢复以前的设备**，
或用 `pocox pair restore`。要在点 **开始使用**、**这是我的第一台设备**、**继续使用** 或
**关联** 之前做：设备一旦设置好，就只能作为新设备重新加入它的组。

- **用匹配码**：输入组里任意一台设备的匹配码，再选出这台设备原来是哪一台。今天还活跃过的
  设备会再确认一次，因为恢复它会让那边停止工作。
- **让已关联的设备允许**（手边没有匹配码时）：这台设备显示一个核对数字。在已关联的设备上，
  **设置 › 账户** 会显示带同一个数字的请求；在那里点 **允许**（终端里用
  `pocox devices allow`），再回到这台设备确认。后端靠硬件找到这台设备，所以只在 macOS、
  Windows 和 Android 8 及以上可用，必须是同一台硬件，手机恢复出厂设置后也不行。iOS、Linux
  或恢复过出厂设置的手机请用匹配码。
- 随时都可以改为 **作为新设备继续**。

如果你的某台设备在你不知情的情况下被恢复到了别处，那台设备会提示这件事以及它停止工作的
时间，并提供 **重新接管并更换匹配码**：另一份的访问立即失效，匹配码随之更换。在那台设备的
终端里，先运行 `pocox pair start-over`，再运行 `pocox pair restore --retake`；在尚未设置的
替换设备上，只需 `pocox pair restore --retake`。

### 设置 › 账户

列出所有已关联的设备，可以重命名和移除。**添加设备** 显示这台设备的匹配码和二维码。
恢复请求和它们的核对数字也显示在这里。此外还有：

- **允许通过匹配码关联**：关掉后匹配码暂停，打开之前谁都不能用它关联。
- **更换匹配码**：作废当前的匹配码，每天最多一次。
- **改为关联其他设备**：加入另一个组。
- **离开这些设备**：这台设备以自己的匹配码单独继续。
- **改用 GitHub 登录** 回到 GitHub 账号；在 GitHub 或自建中转的安装上，**使用匹配码**
  可以回来。

终端里也都有：`pocox devices`、`pocox devices remove`，以及 `pocox pair pause`、
`resume`、`rotate` 和 `leave`（见 [CLI](cli.md#pairing-codes)）。

### 重装

设备的身份保存在一个私有的存储里。手机不会把它放进备份，所以备份无法把它恢复到另一台
手机上；在电脑上它是你用户数据里的一个文件：

| 平台 | 重装之后 |
| --- | --- |
| iOS | 身份在钥匙串里，只属于这台设备，所以删除再重装 App 通常会接着用（Apple 不保证）：同一台设备，同一个匹配码。 |
| Android | 身份在不会被任何备份复制的应用存储里，卸载会删除它。本机的 Block Store 副本可能在同一台手机上把它找回来，但不保证：需要 Android 8 及以上、Google Play 服务并打开 Google 备份，且尚未在真机上测试。 |
| macOS、Windows、Linux | 身份在这个系统账户的应用数据里，这个账户下的所有 POCOX（包括 CLI）共用，重装 App 不受影响。备份或迁移主目录会把它一起复制（只有 macOS 的时间机器会跳过它）。复制到另一台电脑上的副本就等于这台设备：在你的其他设备上移除这台设备，或用 `pocox pair start-over` 再 `pocox pair restore --retake` 把它接管回来。 |

没有身份的设备会回到第一屏：按上面的方法恢复（iOS 和 Linux 上用匹配码），或作为新设备
继续。

### 被移除的设备还保留什么

移除一台设备会立即停止它的**新**连接。已经通过中转的连接会关闭；已经建立的直连（P2P）
可能持续到任一端关闭它，所以 App 说的是“新连接已停止”。被移除的设备保留自己的会话和
设置，可以单独继续使用。一台设备的身份在别处被恢复后，它的旧密钥还能用 600 秒，之后停止；
旧设备会提示这件事，并提供重新接管。

## 2. 用 GitHub 登录

### App

两种 GitHub 登录都在 **其他登录方式** 里：

- **使用 GitHub 登录** 会在浏览器里打开 GitHub；授权后浏览器把你送回 App。
- **GitHub 设备码** 会显示一个短验证码；在 `github.com/login/device` 输入并授权。

两种方式最后都会进入主界面，顶部显示当前登录的账号。

### CLI

```bash
pocox login
```

它会打印一个验证网址和一次性验证码。打开网址、输入验证码、完成授权。用以下命令
确认：

```bash
pocox account     # → 已登录为 @you，模式 = account
```

## 3. 暴露你的 Codex（宿主机）

在已安装并登录 `codex` 的机器上：

```bash
pocox serve
```

它会启动（或复用）本地的 `codex app-server`，并以你的账号注册它。让它保持运行
——这就是其它设备要连接的目标。

常用选项：

- `--name work`——同时跑多个（每个服务用不同的名字区分）。
- `--proxy http://…`——通过上游代理访问 `chatgpt.com`。

## 4. 从任意设备驱动

把另一台设备关联进来（第 1 节），或在它上面登录**同一个** GitHub 账号，然后：

### App（推荐）

主界面会列出你的 app-server，并带一个实时健康状态点。点进去后：

- **新建对话**（**＋** 按钮）；选择一个工作目录。
- 输入提示词并发送。**思考**与**工具调用**会带着计时实时显示。
- 输入框上的控件：**模型**、**审批模式**、**工作目录**、**计划模式**、
  **思考强度**。
- **审批**——当 Codex 请求执行命令或应用补丁时，在此就地批准或拒绝。
- **停止**可中断正在进行的回合。
- 随时重新打开一个对话即可查看历史——若某个回合仍在进行，还会显示实时进度。

### CLI

```bash
pocox services list      # 查看你注册的服务
pocox connect            # 订阅；打印出对应的 codex 命令
codex --remote ws://127.0.0.1:28080
```

`connect` 会把远端的 app-server 暴露到本地端口，并打印出用于连接它的
`codex --remote …` 命令。当你有多个时，用 `--device <id>` / `--name <name>`
指定具体的宿主/实例。

## 5. 作为 OpenAI 兼容 API 使用（可选）

把你的 Codex 登录当作标准的 Responses API，从任意设备访问。

在宿主机上：

```bash
pocox api serve
```

在任意设备上：

```bash
pocox api connect        # 打印一段本地 model_providers 配置片段
```

把任意 OpenAI 兼容工具指向打印出的本地地址即可（它提供 `/v1/responses`）。
在 App 中，API 服务会出现在主界面，并带有自己的健康指示。

## 6. 状态与登出

```bash
pocox account            # 你是谁 + 传输模式
pocox status             # 本地 serve / api / codex 的状态
pocox stop               # 停止本地的 serve / api
pocox logout             # 吊销会话并清除本地令牌
```

在 App 中：**设置 → 账户 → 退出登录**。对匹配码设备，`pocox logout` 和 **退出登录**
只让这个安装退出，身份和组都保留：`pocox pair` 或第一屏的 **继续使用** 可以接着用。
要终止一台设备的访问，请在另一台设备上移除它。

## 常见问题

- **App 里显示「app-server 不可达」**——宿主机上的 `pocox serve` 没在
  运行，或连接已断开。在宿主机上（重新）启动它。App 会周期性重新探测；用刷新
  控件可立即检查。
- **登录过期**——再次运行 `pocox login`。会话有效期内会自动刷新，所以
  每台设备通常只需登录一次。
- **多个宿主或服务**——分别给每个起一个 `--name`，然后在 CLI 用 `--name` /
  `--device` 选择，或在 App 中点击对应的服务。
